# AI-часть AI Sana: инструкция для бэкенда

Python 3.10+, внешние библиотеки не нужны. Модуль использует OpenAI Responses API
через стандартный urllib. Названия полей совпадают с create_task() в ветке backend,
проверенной при разработке. Маршрут HTTP ещё не реализован в бэкенде:
ниже предложен контракт POST /api/ai/clarify; его нужно подключить у владельца бэкенда.

## Быстрый запуск

Из корня репозитория:

```powershell
python -m task_ai examples/ai_input.json --offline
python -m unittest discover -s tests -v
```

Резервный режим работает без ключа и интернета. Он явно возвращает mode="fallback".
Это шаблонная заглушка: она проверяет пустые поля и использует несколько отраслевых
шаблонов; она не понимает произвольный текст и может повторить вопрос, ответ на
который есть только в description. Режим OpenAI анализирует description и fields вместе.

## Вызов из бэкенда

```python
from task_ai import analyze_task, InputValidationError

try:
    response = analyze_task(
        description="Хотим сократить ожидание заказа в кафе",
        fields=task,  # dict из create_task(), включая confirmed, если он есть
    )
except InputValidationError as error:
    # Вернуть HTTP 400/422 с понятной ошибкой входа.
    ...
```

Функция синхронная. В асинхронном обработчике используйте
await asyncio.to_thread(analyze_task, description, fields).
Вход пользователя не должен управлять OPENAI_API_KEY, моделью или URL API.

Не вызывайте API на каждое нажатие клавиши. Достаточно кнопки «Уточнить задачу».
Ограничение частоты запросов, проверка прав и HTTP-маршрут — ответственность бэкенда.

## Вход JSON

```json
{
  "description": "В нашем кафе посетители долго ждут заказ.",
  "fields": {
    "title": "Сокращение ожидания в кафе",
    "users": "Посетители кафе"
  }
}
```

Допустимые поля: title, context, need, users, data, constraints, result,
success_criteria, contact, interaction. Все значения — строки; неизвестное — "".
Поля можно не передавать. confirmed — необязательный boolean, не дающий AI права
подтвердить карточку. Неизвестные ключи отклоняются: передавайте поля карточки,
а не целиком запись базы с id и owner_id.

description: максимум 12000 символов; отдельное поле: максимум 4000;
общий текст: максимум 50000. Нужен хотя бы один непустой текст.

## Выход JSON

Полный воспроизводимый пример: ../examples/ai_output_offline.json.
Поля ответа:

| Поле | Значение |
|---|---|
| schema_version | "1.0" |
| mode | "openai" или "fallback" |
| fallback_reason | null при успехе, иначе машинный код причины |
| requires_confirmation | всегда true |
| card | копия введённых полей, отсутствующие поля "", confirmed=false |
| missing_fields | массив имён полей с недостаточными сведениями |
| questions | 3–6 объектов {"field": "...", "question": "..."} |

card не содержит сгенерированных AI фактов. Модуль НЕ извлекает и НЕ переписывает
карточку из description: описание используется для анализа и вопросов.
Это выбранная AI-функция MVP; генерация карточки не нужна для её использования.
AI может отметить непустое, но расплывчатое поле как требующее уточнения.
Даже для полной карточки возвращаются минимум три вопроса для проверки деталей;
это не означает, что заполненные поля обязательно считаются отсутствующими.

Фронтенду:
1. Покажите questions и режим работы. При fallback напишите «Резервные вопросы».
2. Ответы пользователь записывает в соответствующие поля редактируемой карточки.
3. После правок можно повторно вызвать анализ.
4. Подтверждение и публикация — отдельные ручные действия.
5. Рейтинг рассчитывает существующий бэкенд, не AI.

Ответ card — проект для редактирования. Не перезаписывайте им опубликованную
карточку без действия пользователя: AI всегда возвращает confirmed=false.

## Настройка настоящего OpenAI

Скопируйте .env.example в .env в корне проекта и впишите ключ локально.
Файл .env игнорируется Git. Не используйте ключ в браузерном коде.
Модель настраивается OPENAI_MODEL; по умолчанию gpt-4o-mini.
Доступ к модели и наличие API-кредитов зависят от аккаунта.

```powershell
python -m task_ai examples/ai_input.json --env-file .env
```

При успехе проверьте mode="openai" и fallback_reason=null.
Сам файл .env модуль при импорте НЕ читает. Бэкенд должен загрузить эти переменные
своим способом. Только демонстрационная CLI имеет флаг --env-file.
CLI поддерживает KEY=value, необязательные кавычки и отдельные строки-комментарии.
Подстановки переменных и комментарии после значений не поддерживаются.
Уже заданные переменные окружения имеют приоритет.

OPENAI_TIMEOUT_SECONDS: число от >0 до 60, по умолчанию 15.
Это таймаут сетевых операций urllib, а не строгий общий дедлайн HTTP-запроса
с учётом DNS и всех фаз. Автоматических повторов нет.
store=false передаётся в OpenAI API; это не обещание отсутствия любых журналов провайдера.

## Ошибки и резервный режим

| fallback_reason | Значение |
|---|---|
| offline_requested | Явно включён offline=True / --offline |
| missing_api_key | Нет ключа |
| invalid_configuration | Неверная модель/таймаут в настройках |
| authentication_error | HTTP 401 |
| access_denied | HTTP 403 |
| rate_limit | HTTP 429, включая возможное ограничение квоты |
| api_error | Другая HTTP-ошибка, например 500 или недоступная модель |
| timeout | Сетевой таймаут |
| network_error | Проблема сети |
| invalid_response | Неверный JSON/схема, дубликаты, меньше трёх вопросов |
| incomplete_response | Ответ не завершён, например закончился лимит токенов |
| refusal | Модель отказалась отвечать |

Ошибки провайдера не передаются клиенту сырым текстом, ключ не выводится в лог.
Ошибочный вход пользователя вызывает InputValidationError, а не скрывается заглушкой.

## Проверки и ограничения

Тесты проверяют успешный ответ через подменённый HTTP-транспорт, содержание запроса,
ошибки API, таймаут, отказ, повреждённый JSON, валидацию входа, сохранность карточки,
полную карточку, минимум вопросов и CLI. Они не расходуют API-кредиты.
Успех этих тестов не доказывает доступ к вашему OpenAI-аккаунту:
живую проверку нужно выполнить отдельно с ключом.

Промпт находится в task_ai/prompts.py, JSON Schema — в task_ai/schema.py.
Промпт запрещает выдуманные факты и инструкции из пользовательского текста.
Схема контролирует структуру, но не гарантирует смысловую правильность вопросов:
человек проверяет их и подтверждает карточку.

Официальный формат API:
https://developers.openai.com/api/docs/guides/structured-outputs

## Как забрать AI-часть

Ветка: ai/task-clarification. Владелец бэкенда может проверить diff и добавить
коммиты этой ветки в свою ветку. main автоматически не меняется.
Пакет task_ai импортируется из корня репозитория; pip install не нужен.

Передать бэкенду: пакет task_ai/, .env.example, examples/ai_input.json,
examples/ai_output_offline.json и эту инструкцию. tests/ — проверки для команды.

## Подключение к текущему Streamlit-фронтенду

Проверены ветки frontend (b76a62a) и backend (817873a). app.py использует
Streamlit, поэтому analyze_task можно вызывать на стороне Python напрямую,
без отдельного HTTP-маршрута. Предложенный выше /api/ai/clarify нужен только
если команда решит вынести API отдельно.

В текущем frontend критерии успеха названы success; в backend и AI —
success_criteria. При интеграции согласуйте единое имя success_criteria.
Поля industry, id, status, score не входят в AI-контракт: выбирайте только FIELDS.
Пример адаптации текущей карточки (это фрагмент, не готовая замена app.py):

```python
from task_ai import FIELDS, analyze_task

fields_for_ai = {name: task.get(name, "") for name in FIELDS}
if not fields_for_ai["success_criteria"]:
    fields_for_ai["success_criteria"] = task.get("success", "")
analysis = analyze_task(description, fields_for_ai)
```

Лучше разместить свободное описание и кнопку AI ДО подтверждения карточки.
После нажатия сохраните результат в st.session_state, чтобы перерисовка страницы
не вызывала повторный платный запрос. Отобразите mode, fallback_reason и вопросы;
ответы внесите в редактируемую форму, затем попросите ручное подтверждение.
Ключ задаётся в окружении процесса Streamlit на сервере. Импорт task_ai сам
не загружает .env. На вашем хостинге используйте настройки секретов либо уже
принятый в бэкенде механизм загрузки переменных окружения.
```.env``` и ключ не нужно передавать через GitHub.
