# AI Sana — QyzCode

Работающий прототип для пятичасового хакатона: бизнес превращает краткую потребность
в карточку задачи, повышает её рейтинг готовности и публикует в открытом каталоге.
Студенты самостоятельно предлагают решения, а бизнес вручную выбирает команды.

**Стек:** Python 3.10+, Streamlit, SQLite, OpenAI Responses API.
Приложение можно показать без интернета и API-ключа, используя явно обозначенный
резервный режим уточняющих вопросов.

## Что реализовано

- Свободное описание задачи и 3–6 уточняющих вопросов от AI.
- Редактируемая карточка, перенос ответов пользователя и ручное подтверждение.
- Рейтинг 0–100 с расшифровкой, подсказками и пересчётом после подтверждения.
- Публикация, общий каталог, сортировка по рейтингу, фильтры по теме и готовности.
- Профили команд, предложения с идеей, планом, сроком и ссылкой на прототип.
- Ручной выбор одной или нескольких команд либо отклонение всех предложений.
- Подтверждение фактического результата этапа: +10 баллов выбранной команде.
- Сохранение в SQLite и синтетические данные для демонстрации.

ИИ не назначает команды, не начисляет рейтинг и не подтверждает сведения за человека.

## 2. Установка и запуск

### Windows / PowerShell

Установите обычный Python 3.10+ с поддержкой venv и pip. Проверьте его запуск:

```powershell
py --version
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Если py отсутствует, но работает python, используйте python вместо py в первых двух
командах. Активация виртуального окружения не нужна. Для повторного запуска достаточно
последней команды.

### macOS / Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

Откройте напечатанный Streamlit адрес, обычно http://localhost:8501.
Для остановки нажмите Ctrl+C в терминале.
При занятом порте добавьте --server.port 8502 к команде запуска.

SQLite-файл ai_sana.db создаётся автоматически рядом с database.py.
Отдельная установка сервера базы данных не требуется. Сохранённые данные переживают
перезапуск; удаление файла базы приведёт к потере этих данных.
Файл базы, окружение .venv и секреты исключены из Git.

## 3. Настройка OpenAI

Для начала можно оставить ключ пустым и пользоваться резервными вопросами.

Для настоящего AI:
1. Скопируйте .env.example в .env рядом с app.py.
2. Вставьте свой API-ключ после OPENAI_API_KEY=.
3. Сохраните файл и перезапустите Streamlit.
4. Снимите галочку «Использовать резервные вопросы без API».
5. Введите описание и нажмите «Уточнить с ИИ».

Пример настроек, без настоящего ключа:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4o-mini
OPENAI_TIMEOUT_SECONDS=15
```

| Переменная | Назначение |
|---|---|
| OPENAI_API_KEY | Ключ проекта OpenAI, хранится только на сервере |
| OPENAI_MODEL | Доступная вашему аккаунту модель, по умолчанию gpt-4o-mini |
| OPENAI_TIMEOUT_SECONDS | Таймаут сетевых операций, >0 и не более 60 секунд |

Настройки процесса имеют приоритет над .env. После изменения ключа перезапустите
сервер, чтобы не использовать старое значение из окружения.
Простая загрузка .env поддерживает KEY=value и необязательные кавычки,
но не подстановки переменных. Не добавляйте комментарии после значения ключа.

Настоящий запрос расходует API-кредиты. Ключ не отправляется в браузер,
не сохраняется в карточку и не должен попадать в GitHub или переписку.
Он нужен на том компьютере или сервере, где запущен Streamlit.

### Проверка AI отдельно от интерфейса

```powershell
.\.venv\Scripts\python.exe -m task_ai examples/ai_input.json --env-file .env
.\.venv\Scripts\python.exe -m task_ai examples/ai_input.json --offline
```

В ответе mode=openai означает настоящий ответ API; mode=fallback — резервный режим.
Причина находится в fallback_reason. Полный [контракт AI](docs/AI_INTEGRATION.md),
[пример входа](examples/ai_input.json) и [резервного ответа](examples/ai_output_offline.json).

Повторная загрузка не дублирует уже загруженные карточки и не удаляет пользовательские.

## 5. Пользовательский сценарий

### Бизнес: от описания до публикации

1. Выберите режим «Бизнес» и раздел «Создать задачу».
2. Введите исходное описание, например «У магазина много списаний».
3. Нажмите «Уточнить с ИИ» и проверьте фактический режим работы.
4. Ответьте на вопросы и нажмите «Перенести ответы в карточку».
5. Отредактируйте сведения. Неизвестные поля можно оставить пустыми.
6. Поставьте галочку подтверждения и нажмите «Подтвердить и сохранить карточку».
7. Посмотрите рейтинг и расшифровку. Дополните поля и подтвердите снова для его роста.
8. Нажмите «Опубликовать сохранённую карточку».

Название и потребность необходимы для подтверждения и публикации.
Черновик можно сохранить без подтверждения.
Ответы на вопросы добавляются к существующим сведениям, не заменяя их автоматически;
человек может отредактировать итоговый текст.

### Студенты: выбор задачи и отклик

1. Выберите режим «Команда» и «Каталог задач».
2. Посмотрите задачи и при необходимости установите фильтры.
3. Создайте или выберите профиль команды.
4. Откройте задачу, введите идею, план, срок и ссылку на прототип.
5. Отправьте предложение. Ссылка должна начинаться с http:// или https://.

Рейтинг задачи не ограничивает право откликнуться. Автоматического назначения нет.

### Бизнес: выбор команды и подтверждение этапа

1. Перейдите в «Кабинет бизнеса».
2. Просмотрите предложения и ссылки на прототипы.
3. Нажмите «Выбрать» или «Отклонить» для каждого предложения вручную.
4. Для выбранной команды опишите проверенный результат этапа.
5. Подтвердите получение результата и нажмите «Подтвердить этап: +10 баллов».

Решение по одному отклику не меняет другие. Можно выбрать несколько команд или ни
одной. За отправку отклика и сам выбор баллы не начисляются.
Для одного предложения доступен один подтверждаемый этап. Повторное начисление
блокируется в базе. Уже заработанные баллы сохраняются, даже если решение позже меняется.

## 6. Формула рейтинга и правила каталога

В calculate_rating() рейтинг — сумма весов семи групп:

| Группа | Обязательные поля группы | Максимум |
|---|---|---:|
| Контекст и потребность | context, need | 20 |
| Данные и материалы | data | 20 |
| Ожидаемый результат | result | 15 |
| Критерии успеха | success_criteria | 15 |
| Ограничения | constraints | 10 |
| Пользователи | users | 10 |
| Связь с бизнесом | contact, interaction | 10 |
| **Итого** | | **100** |

Каждая группа получает полный вес, если все её поля — непустые строки и карточка
подтверждена. Иначе группа получает 0. Пробелы не считаются заполнением.
Название и тема отдельные баллы не добавляют.
Формула проверяет полноту, не достоверность или смысловую полезность текста;
это ограничение MVP, за подтверждение отвечает человек.

| Баллы | Уровень |
|---|---|
| 0–39 | Черновик |
| 40–69 | Рабочая |
| 70–89 | Готовая |
| 90–100 | Приоритетная |

- В каталог попадают только опубликованные задачи, доступные всем командам.
- Опубликованная задача уровня «Черновик» видна и принимает отклики.
- Неопубликованный черновик и низкий уровень готовности — разные состояния.
- Сортировка — по убыванию рейтинга; фильтры по теме и уровню добровольны.
- Количество предложений не ограничивается рейтингом или числом выбранных команд.
- При редактировании по id обновляется существующая запись.
- Сохранение неподтверждённого черновика снимает задачу с публикации.
  После подтверждения её можно опубликовать снова.
- Подтверждённые изменения опубликованной карточки сохраняют публикацию.
- На странице показан рейтинг последней сохранённой версии, а не неотправленной формы.

## 7. Архитектура и структура проекта

```text
Браузер пользователя
        │
        ▼
app.py — Streamlit, формы и демонстрационные роли
        ├── integration.py → task_ai → OpenAI Responses API
        │                              └── резервные вопросы
        ├── backend.py — рейтинг и каталог
        └── database.py — SQLite: задачи, команды, предложения и этапы
```

Это одно Python-приложение. Отдельный Node.js-сервер, REST API, векторная база
и обучение собственной модели не требуются.

| Путь | Ответственность |
|---|---|
| app.py | Конструктор, AI-вопросы, каталог, отклики, кабинет бизнеса |
| backend.py | create_task(), calculate_rating(), get_catalog() |
| database.py | SQLite, публикация, редактирование, команды, предложения, этапы |
| integration.py | Нормализация полей и перенос ответов пользователя |
| task_ai/service.py | Запрос Responses API и резервный режим |
| task_ai/prompts.py | Инструкция для модели |
| task_ai/schema.py | JSON Schema, проверка входа и ответа |
| task_ai/fallback.py | Локальные шаблонные вопросы |
| seed_demo.py, examples/ | Синтетические данные и примеры AI |
| styles.css, .streamlit/config.toml | Оформление интерфейса |
| tests/ | Проверки AI, логики, данных и Streamlit-интерфейса |
| requirements.txt | Зависимости общего приложения |

Карточка содержит title, topic, description, context, need, users, data, constraints,
result, success_criteria, contact, interaction, confirmed.
Старые имена industry и success преобразуются адаптером.
AI принимает только поля из task_ai.FIELDS и исходное description:
id, topic, status и score внутрь fields не передаются.

## 8. Содержательная AI-функция

OpenAI анализирует описание вместе с заполненными полями и возвращает:
- missing_fields — сведения, которых не хватает или которые требуют конкретизации;
- questions — 3–6 вопросов с привязкой к полям карточки;
- card — копию введённых полей без сгенерированных фактов;
- requires_confirmation=true и card.confirmed=false;
- mode и fallback_reason — фактический режим обработки.

Промпт запрещает выдумывать факты, выполнять инструкции из пользовательского текста,
назначать команды и начислять баллы. Используется структурированный ответ JSON Schema,
затем локально проверяются поля, типы, количество и уникальность вопросов.
Даже полная карточка получает минимум три вопроса для уточнения деталей.

Пустой ключ, таймаут, HTTP-ошибка, отказ модели, незавершённый или неправильный ответ
включают fallback. Интерфейс показывает резервный режим и причину.
Резервный режим — шаблонная заглушка, а не локальная языковая модель:
он может повторить вопрос, ответ на который есть только в свободном описании.
Некорректный вход вызывает InputValidationError.

API вызывается по кнопке. Результат сохраняется в сессии, чтобы перерисовка
страницы не создавала повторный платный запрос.
Таймаут относится к сетевым операциям, не является строгим общим дедлайном всех фаз.
Схема гарантирует проверку структуры, но не смысловую безошибочность: человек
проверяет вопросы, редактирует карточку и подтверждает её.

## 9. Проверки и воспроизведение

Полный набор, после установки requirements.txt:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют временные базы и подменённый HTTP-транспорт.
Платные запросы OpenAI при запуске набора не выполняются.

| Проверка | Ожидаемый результат |
|---|---|
| Пустой вход | Понятная ошибка, без сохранения подтверждённой карточки |
| Слабое описание | Не менее трёх вопросов, режим AI явно показан |
| Ошибка API | Резервные вопросы и код причины |
| Перенос ответов | Существующие факты сохранены, подтверждение сброшено |
| Дополнение и подтверждение | Рост рейтинга, корректная расшифровка |
| Публикация слабой задачи | Задача доступна в каталоге и принимает отклик |
| Редактирование | Та же запись и id, без дубликатов |
| Выбор двух команд | Оба решения сохранены независимо |
| Подтверждение этапа | +10 выбранной команде; повторное начисление запрещено |
| Повторная загрузка демоданных | Нет дубликатов и потери существующих задач |

test_app.py проходит пользовательский путь через Streamlit AppTest, включая выбор
команды и этап. test_integration.py проверяет логику, test_demo.py — загрузку данных,
test_task_ai.py — AI и ошибки.

При подготовке этого README локально повторно пройдены **7 тестов интеграции и
демоданных**. Ранее AI-часть прошла **16 тестов** и отдельный живой запрос OpenAI.
Полный набор с Streamlit UI в этой проверке README повторно не запускался.
Тесты с подменой не доказывают наличие кредита или доступа к модели;
настоящий запрос проверяется отдельно с ключом.

## 10. Демонстрация до пяти минут

1. **0:00–0:40:** введите слабое описание магазина, получите минимум три вопроса.
2. **0:40–1:30:** ответьте, перенесите сведения и отредактируйте карточку.
   Для наглядного начала оставьте только название, контекст и потребность:
   после подтверждения это 20 баллов.
3. **1:30–2:15:** добавьте пользователей (+10), данные (+20) и другие сведения.
   Подтверждайте изменения и покажите рост рейтинга и подсказки.
4. **2:15–2:45:** опубликуйте карточку; покажите каталог, сортировку и фильтры.
5. **2:45–3:40:** переключитесь на команду, выберите задачу и отправьте предложение.
6. **3:40–4:30:** вернитесь в бизнес, сравните отклики и вручную выберите команду.
7. **4:30–5:00:** подтвердите проверенный результат этапа и покажите +10 баллов.

Перед выступлением загрузите демоданные и проверьте весь путь на том ноутбуке,
с которого будете показывать сайт. Для настоящего AI проверьте сеть и ключ;
при недоступном API честно покажите резервный режим, промпт и JSON-контракт.

## 11. Ограничения MVP

- Нет регистрации и разграничения доступа. Роли — демонстрационный переключатель,
  все задачи доступны в кабинете бизнеса. Для публичного использования нужна авторизация.
- Сохранение данных реализовано в локальной SQLite, без облачной синхронизации ноутбуков.
- Один подтверждаемый этап на предложение; полноценного трекера нет.
- Нет чата, уведомлений, файлового хранилища и автоматического подбора исполнителей.
- Несохранённые изменения формы могут потеряться при переходе между разделами.
- Текстовая полнота не означает проверенную осуществимость бизнес-задачи.

Разработка разделена на ветки frontend, backend и ai/task-clarification.
Собранное приложение с этой документацией находится в docs/full-readme.
Перед сдачей команда выбирает итоговую ветку или архив; main автоматически
не изменялся. В архив не включайте .env, .venv и локальную базу с пользовательскими данными.
