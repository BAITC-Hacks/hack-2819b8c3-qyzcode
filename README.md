# AI Sana — QyzCode

MVP для уточнения бизнес-задач и открытого выбора студенческих команд.
Бизнес описывает потребность, дополняет карточку и подтверждает сведения.
Рейтинг готовности показывает полноту конкретной задачи. Студенты выбирают
задачи сами, а бизнес вручную принимает решение по откликам.

## Состояние этой ветки

Ветка `ai/task-clarification` содержит самостоятельную AI-часть, её проверки и документацию.
В ней нет полного сайта, базы данных или готового веб-маршрута.

- AI-модуль работает через OpenAI Responses API; живой запрос проверен.
- При отсутствии ключа или ошибке API доступны явно обозначенные резервные вопросы.
- Пройдены 16 автоматических тестов без обращения к внешнему API.
- Отдельные ветки команды: `frontend` — Streamlit, `backend` — логика и SQLite.
- Проверка веток 23.09.2026: в frontend уже добавлен адаптер integration.py,
  однако app.py ещё не вызывает AI; каталог и кабинет бизнеса в интерфейсе —
  заглушки. Полный сквозной сценарий пока нельзя считать проверенным.

## Архитектура

```text
Streamlit-интерфейс (Python, ветка frontend)
  ├─ integration.py → task_ai.analyze_task() → OpenAI Responses API
  │                                         └─ локальная заглушка при ошибке
  └─ backend.py → рейтинг, каталог → database.py → SQLite
```

Streamlit выполняет Python-код на сервере: AI-модуль можно вызывать напрямую.
Отдельный HTTP-сервис для этого не обязателен.
Секретный ключ хранится в окружении серверного процесса, не в браузере.

AI не выставляет рейтинг, не выбирает команду и не подтверждает карточку.
Рейтинг и ручные действия бизнеса реализуются в основной логике приложения.

## Запуск AI-части

Нужен Python 3.10 или новее и Git. Дополнительные Python-библиотеки для AI не нужны.

```powershell
git clone --branch ai/task-clarification https://github.com/BAITC-Hacks/hack-2819b8c3-qyzcode.git
cd hack-2819b8c3-qyzcode
python --version
python -m task_ai examples/ai_input.json --offline
```

Приватный репозиторий требует входа в GitHub с правами доступа.
Если проект уже скачан, запускайте команды Python из его корневой папки.

### Настоящий OpenAI

1. Скопируйте `.env.example` в `.env`.
2. Локально заполните OPENAI_API_KEY. Не добавляйте ключ в GitHub и переписки.
3. Запустите:

```powershell
python -m task_ai examples/ai_input.json --env-file .env
```

Успех: `mode="openai"`, `fallback_reason=null`.
Резервный режим: `mode="fallback"`; поле fallback_reason объясняет причину.
Ключ проверяется реальным API-запросом, который расходует API-кредиты аккаунта.

| Настройка | Назначение |
|---|---|
| OPENAI_API_KEY | Секретный ключ OpenAI |
| OPENAI_MODEL | Модель, по умолчанию gpt-4o-mini |
| OPENAI_TIMEOUT_SECONDS | Таймаут сетевых операций, по умолчанию 15 секунд |

Файл .env читает только демонстрационная команда с --env-file.
Бэкенд загружает окружение собственным способом.
Пустой ключ автоматически включает заглушку.

### Проверки

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют контракт запроса и ответа, сохранность полей, минимум вопросов,
ошибки HTTP, таймаут, обрыв ответа, отказ модели, неверный JSON и запуск CLI.
Сетевой транспорт подменяется; тесты не расходуют деньги.
Отдельно успешно выполнен живой запрос OpenAI на синтетическом примере кафе.

## AI-контракт и подключение

```python
from task_ai import FIELDS, analyze_task

# Не передавайте id, topic, score и другую служебную информацию внутрь fields.
fields = {name: task.get(name, "") for name in FIELDS}
response = analyze_task(description, fields)
```

Функция возвращает:
- missing_fields — поля с недостаточными сведениями;
- questions — от 3 до 6 вопросов с привязкой к полю;
- card — введённые пользователем поля без AI-переписывания, неизвестные поля пустые;
- requires_confirmation=true и card.confirmed=false;
- mode и fallback_reason — фактический режим и причина резервного ответа.

Ответы вносит пользователь; подтверждение остаётся отдельным действием.
Простая заглушка не понимает произвольный текст так же, как LLM:
она ориентируется на пустые поля и несколько отраслевых шаблонов.
Структурная проверка ответа не гарантирует смысловую безошибочность вопросов.

Полная [инструкция интеграции](docs/AI_INTEGRATION.md), [пример входа](examples/ai_input.json),
[пример резервного ответа](examples/ai_output_offline.json) и [промпт](task_ai/prompts.py).

## Формула рейтинга задачи

Ниже описана функция calculate_rating из ветки backend, проверенной при подготовке
README. Она не входит в AI-пакет. Для каждой группы начисляется полный вес, если
все её поля — непустые строки и карточка подтверждена; иначе группа получает 0.

| Группа | Поля | Баллы |
|---|---|---:|
| Контекст и потребность | context, need | 20 |
| Данные и материалы | data | 20 |
| Ожидаемый результат | result | 15 |
| Критерии успеха | success_criteria | 15 |
| Ограничения | constraints | 10 |
| Пользователи | users | 10 |
| Связь с бизнесом | contact, interaction | 10 |
| **Всего** | | **100** |

Рейтинг = сумма баллов семи групп. Это проверка полноты, а не истинности текста.
Название и тема используются в карточке/каталоге, но отдельных баллов не добавляют.

Уровни: 0–39 — «Черновик»; 40–69 — «Рабочая»;
70–89 — «Готовая»; 90–100 — «Приоритетная».
После изменения и повторного подтверждения карточки рейтинг пересчитывается.

## Правила общего каталога

По условиям кейса и для итоговой интеграции:
- опубликованные задачи доступны всем командам;
- сортировка — по убыванию рейтинга, фильтры — тема и уровень готовности;
- низкий рейтинг не скрывает опубликованную задачу и не запрещает отклик;
- неопубликованный черновик и опубликованная задача уровня «Черновик» — разные состояния;
- команда сама отправляет идею, план, срок и ссылку на прототип;
- бизнес может выбрать одну, несколько или ни одной команды, без автоназначения;
- баллы за этап работы начисляются только после подтверждения результата бизнесом.

Логика каталога и откликов развивается в backend; подключение к UI проверяет
ответственный за сборку общего приложения.

## Сценарии проверки

| Сценарий | Ожидаемый результат |
|---|---|
| Слабое описание кафе | AI задаёт минимум 3 уместных вопроса |
| Полностью заполненные поля | Минимум 3 вопроса для уточнения деталей, введённые факты сохранены |
| Пустой вход / неверный тип поля | InputValidationError, обработчик возвращает понятную ошибку |
| Нет ключа / сеть недоступна / неверный ответ API | mode=fallback, объяснение причины, доступные резервные вопросы |
| Ответ AI | Нет автоматического подтверждения, рейтинга или выбора команды |
| Весь сайт после интеграции | Описание → вопросы → ответы → подтверждение → рост рейтинга → публикация → отклик → ручной выбор |

### Демонстрация до 5 минут

Введите «Хотим сократить очереди в кафе», получите вопросы и дополните карточку.
Покажите рост рейтинга после подтверждения, публикацию и позицию в каталоге.
От лица команды отправьте предложение; от лица бизнеса вручную выберите команду.
Этот сквозной сценарий нужно репетировать на собранном сайте, а не только в AI CLI.

## Что команда добавляет перед сдачей

- Проверенный запуск общего сайта. В frontend есть requirements.txt; предполагаемые
  команды для этой ветки: python -m pip install -r requirements.txt и
  python -m streamlit run app.py. В данной AI-ветке app.py отсутствует.

- Минимум 5 черновиков, 5 карточек, 5 профилей команд и 5 предложений.
  Один пример кафе в этой ветке не заменяет общий обязательный набор.
- Проверку подтверждения этапа и начисления баллов за фактический прогресс.
- Обновление этого README по фактическому состоянию итоговой ветки и ссылку на демо.

При объединении веток сохраните AI-инструкции и дополните их проверенными
командами запуска общего приложения. Этот README не утверждает, что
ещё не подключённые части сайта уже завершены.
